# 定时任务

在 Web 左侧「定时任务」中创建计划，选择执行员工和工作区，核对显示的执行目录，再填写提示词和执行时间。支持单次、每天、每周及每隔若干小时；重复计划按保存的时区计算。提示词可以直接包含帖子原文和处理要求。

到点后服务会在对应员工私聊中发出这项工作，每次创建一个独立执行会话，以定时任务名称作为初始标题，沿用该员工当前的角色、模型候选及权限配置。会话出现在所选工作区的会话列表中，员工私聊保留当次会话入口；定时任务列表和执行记录中的「查看会话」可直接阅读结果或处理权限请求。保存计划本身不会开始执行或创建空白执行会话；重复计划的每次执行各有自己的会话，历史保留。

计划按项目 ID 绑定执行位置，到点时使用该项目当前的绝对工作目录。项目被删除、目录不存在或不可用时，本次执行会明确失败，不会改用其他项目或服务默认目录。执行记录保留当次的项目 ID 和目录；之后修改计划或项目不会改写已触发记录。未选择项目的旧计划继续使用服务默认目录，可编辑后指定项目。

- 可以编辑、暂停、恢复或取消计划。暂停与取消只影响后续触发，已经开始的执行和历史记录保留；已取消计划可从列表筛选中查看。
- 计划保存在本机数据库，关闭浏览器不影响调度。Wand 服务和主机需要处于运行状态；默认每 15 秒检查一次到期计划。
- 服务恢复后，过期的单次计划补执行一次；重复计划合并错过的周期为一次执行，再计算下一次时间，不批量补跑。
- 同一计划上一轮尚未结束时，本次触发会记为「已跳过」。接收状态不明的执行不会自动重发，可从执行记录核对。
- 每天和每周使用当地日历时间。夏令时中不存在的时间跳过，重复出现的时间只执行第一次。

## 小时间隔计划

「每隔若干小时」在同一计划上保存间隔、首次时间和时区，不创建多个每日计划。间隔为 1–8760 的整数小时，继续绑定原有员工、工作区及提示词。

```json
{"kind":"interval","everyHours":3,"startAt":"2030-01-01T01:00:00.000Z","timeZone":"Asia/Shanghai"}
```

`startAt` 必须包含明确偏移或 `Z`，服务端规范化为 UTC；`timeZone` 为有效 IANA 时区，用于预览和保存后展示。表单的首次时间按本机时区编辑，并明确提示这一点。间隔按真实经过的小时数计算，跨夏令时仍为 3 小时，而不是每天固定 8 个当地钟点。保存前预览和保存后的详情都显示频率、下次时间及其时区。

- 首次时间尚未到：下一次为首次时间。
- 首次时间已过：以首次时间为锚点，取严格晚于当前时间的下个周期；不把保存动作当作立即执行。
- 暂停不停止当前执行。恢复保留锚点，跳过暂停期间的周期，从下个周期继续，不从恢复时间重新计时。
- 服务重启保留 SQLite 中的计划、锚点、下次时间与执行记录；停机漏期沿用现有规则合并补跑一次，再推进到当前时间之后的周期，不展开积压执行。
- 同一到期项沿用原子领取、确定性执行 ID 和回执幂等规则。上一轮仍在运行或已接收待执行时，本次记为跳过，下一周期继续；当前轮接收未知不会重复发送。
- 默认为每 15 秒扫描一次，不是严格实时调度。日历按新规则展开未来预计安排，仍受共享 1000 项读取上限约束；历史只显示实际执行事实。

Mac 原生端目前没有定时模块；完整原生模块或显式 Web 入口需要先确定交付范围。

## 自动压缩与 Tag 要求

每日定时任务会将过去 24 小时已提交的 commit 压缩为单个 commit，随后**必须**打一个新的语义化版本 tag（`v4.x.y` 格式，小写 v）并推送到远程。未打 tag 视为任务未完成，不得视为成功。

- 压缩仅包含已提交的 commit，工作区未提交改动不并入。
- 版本号在现有最高版本基础上递增 minor 版本（如 `v4.91.0` → `v4.92.0`）。
- Tag 由定时任务自动生成并强制推送（`-f`），覆盖同名 tag。
- 远程必须能看到新 tag，否则需报警/重试。

---

HTTP 接口使用现有鉴权及 `sessions` 权限：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/scheduled-tasks?includeCancelled=1` | 包含取消记录的计划列表 |
| GET | `/api/scheduled-tasks/:id` | 计划及最近 50 次执行 |
| POST | `/api/scheduled-tasks` | 创建计划，`requestId` 保证重复请求不会创建两份 |
| PATCH | `/api/scheduled-tasks/:id` | 更新计划，`revision` 防止覆盖其他客户端的修改 |

单次计划使用 `{ "kind": "once", "runAt": "2026-10-12T09:00:00+08:00" }`；每日计划使用 `{ "kind": "daily", "time": "09:00", "timeZone": "Asia/Shanghai" }`；每周计划在每日字段基础上改为 `kind: "weekly"` 并加入 `weekday`（0 为周日，6 为周六）；小时间隔计划使用 `{ "kind": "interval", "everyHours": 3, "startAt": "2030-01-01T01:00:00.000Z", "timeZone": "Asia/Shanghai" }`。

创建或更新计划可传 `workspaceId`，值须是具有可用绝对目录的非全局项目 ID；更新同时传当前 `revision`。为兼容旧客户端，省略 `workspaceId` 或显式传 `null` 表示服务默认目录，更新时省略则保留已有项目。计划列表返回项目名称、当前目录和不可用原因；执行记录中的 `workspaceId`、`cwd` 是当次触发时保存的目标。
