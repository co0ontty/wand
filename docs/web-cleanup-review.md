# Web 架构清理与验收记录

本轮按「分析技术栈 → 确定边界 → 删除确认失效的代码 → 修复与统一视觉 → 实际操作验收」执行。
技术规范见 [Web 技术栈与职责规范](web-architecture.md)。没有新增框架、组件库或状态库。

## 发现与处理

| 问题 | 处理结果 |
| --- | --- |
| React Shell 与 browser 运行时职责容易被误判 | 明确 React 负责页面、browser 负责终端/聊天/连接；保留必要桥接 |
| 旧文件树、搜索、会话管理 CSS 已无消费者 | 全 src 搜索与多状态运行时查询后删除 62 个选择器分支，纯删除阶段净减 346 行 |
| 多个 Repository 重复解析 JSON，坏响应变成成功空对象 | 共用 HTTP 适配器；保留状态码、服务端错误及取消语义 |
| 架构测试仍以 Radix 为目标，与 Appica 实际选型不符 | 统一基础组件入口及依赖边界检查 |
| 环境变量明文预览对 `1` 与 `true` 的权限判断不一致 | 只解析一次 reveal，两种值均要求管理员；增加鉴权回归测试 |
| 非 Git 目录启用 worktree 暴露原始命令错误 | 返回原因和可执行的恢复步骤，失败不创建任务 |
| 登录页与业务弹层视觉不一致 | 共享纸色、暖灰、赤陶色、字体尺寸、圆角及阴影 token，取消部分渐变与玻璃效果 |
| 文件树把同目录全部文件标成选中 | 改为实际打开文件路径；补齐文件树与菜单键盘操作 |
| 编辑器被终端输入栏覆盖 | 修正层级，并在编辑器打开时隔离底层输入交互 |
| 文件路径输入框撑出容器 | 修正 flex 最小宽度与宽度约束 |
| 移动端设置标签和看板工具栏溢出 | 修正组件库默认布局继承、标签方向、工具栏换行及列表自适应 |

真实浏览器使用隔离配置、数据库和测试目录，完成以下操作：

1. 登录，进入 Shell，打开设置、新建任务与任务看板。
2. 创建空白终端任务，提交 `printf` 命令并确认实际 PTY 输出；重启测试 Web 服务后终端重新连接。
3. 展开文件树，打开文件，修改并保存，再从磁盘核对内容。
4. 使用文件树键盘导航、文件菜单上下键、Escape 关闭及焦点恢复。
5. 保存基本设置，切换设置分组。
6. 提交非 Git 目录的 worktree 请求，确认友好错误且表单输入保留。
7. 切换看板/列表视图并搜索任务。
8. 检查桌面及 390 × 844 窄屏下的设置、文件编辑器、任务抽屉、看板和列表。
9. 删除阶段补查折叠、抽屉、弹层、`reactUi=0` 及原生 UA 分支，待删选择器均无命中。

## 验收边界

本轮验证覆盖上述路径，并非所有功能的穷举认证。外部 provider 的真实付费调用、
真实原生设备、完整上传/权限审批/跨 provider resume 链路没有逐项进行端到端验收；
其自动化回归结果不能替代真实服务和设备测试。原生 UA 模拟仅说明 Web 分支正常。

没有修改 Android、iOS 或 macOS 源码，没有调整数据库迁移，也没有合并 PTY 与结构化 runner。

## 产品体验优化（2026-09-17）

技术栈清理后的设计依据写入根目录 `DESIGN.md`，跨页面交互约定写入
`UX-CONTRACT.md`。沿用登录页纸色、暖灰与赤陶色，通过既有 CSS token 和
Wand UI 组件统一业务页面，没有引入第二套设计系统。

本阶段完成：

- 看板统一标题、工具栏、搜索、目录筛选、结果数量与空状态；移动端改为可正常滚动的布局。
- 列表任务使用真正的按钮，避免嵌套可交互元素干扰键盘操作；返回和刷新保留浏览上下文。
- 新建任务两个入口共用草稿放弃确认；默认继续编辑，提交期间防重复操作。
- 归档明确解释影响范围，取消为安全默认；成功通过统一通知反馈。
- 文件搜索共用搜索组件，支持清除并恢复焦点、请求防抖与取消、失败重试。
- 断网错误转为操作相关的中文提示，失败时保留已加载数据；失效目录筛选在成功同步后清除。
- 表单、滚动条、按钮焦点、状态文字对比度与弹层外观统一；可选里程碑默认折叠。
- 删除已失去消费者的旧目录弹窗、展开式搜索及重复返回按钮样式，额外净删 179 行。
  删除前执行全 src 搜索与六种浏览器状态的选择器查询；纯删除补丁和证据保存在隔离验收目录。
