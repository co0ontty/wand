# 创建硅基员工（招聘与入职）

Wand 已有正式的控制台创建流程，不需要直接调用内部 HTTP 接口。

## 入口

在 Web 控制台打开：

**左侧「设置」菜单（账户与设置） → 员工与通讯录 → 管理员工与团队模板 → 员工 → 招聘员工**。

「通讯录」用于查看员工、发起对话；创建员工在其「管理员工与团队模板」入口中。员工管理与团队模板管理不是同一件事：创建团队模板不会自动办理员工入职。

## 手动创建（不请求模型起草）

1. 在「招聘员工」中展开 **人选资料（可手动填写）**。
2. 填写名字、职责、角色设定（Prompt），按需配置标签和头像。
3. 核对执行候选的工具、模型、引擎及权限，至少保留一个有效的结构化候选；不要因招聘而擅自扩大工具权限或付费范围。
4. 点击 **确认入职**。成功后进入该员工资料页，在员工目录可以找到新员工。

手动资料需要保持展开且名字非空，否则主按钮仍按岗位期望请求起草。名字上限 40 字符、职责上限 2000 字符、Prompt 上限 20000 字符；其他校验以表单/服务端提示为准。

## 请 HR 嘟嘟拟定人选

1. 填写岗位期望，点击 **请嘟嘟拟定人选**。此步骤会使用系统配置的模型调用链，须具有相应调用授权与费用范围。
2. 起草结果仅填入人选资料，**不会自动创建员工**。核对名字、职责、Prompt 及全部执行候选，按需修改。
3. 确认无误后点击 **确认入职**，才会保存正式员工定义。

起草失败或入职失败会在表单提示，已输入资料保留。网络中断或结果未知时先回到员工目录核对，不盲目重复创建。离开有修改的表单时按页面提示选择继续编辑或放弃未提交草稿。

## CLI 与授权边界

- `wand employee:list` 查询员工公开定义；`--include-archived` 包含归档员工。
- 当前没有 `employee:create` / `employee:add` 命令；创建请使用上述正式控制台流程，不把不存在的命令或裸 HTTP 请求当作已交付的创建入口。
- `session:create --stdin` 为**已有员工**创建会话，不是创建员工；传入 prompt 会立即接受执行，不能为验证招聘而误启动真实任务。
- 创建员工定义不等于启动工作、设置定时任务或派发团队。创建能力本身不增加操作授权，也不应修改其他员工的配置、权限或历史。
