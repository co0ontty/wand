# 小时间隔计划

Web「定时 → 新建定时任务 → 执行计划 → 每隔若干小时」可保存一个每小时或每3小时计划。间隔为1–8760的整数小时；同一计划继续绑定原有员工、工作区及提示词，不创建多个每日计划。一次、每天、每周的格式与调度规则不变。

协议示例（示例本身不会启用计划）：

```json
{"kind":"interval","everyHours":3,"startAt":"2030-01-01T01:00:00.000Z","timeZone":"Asia/Shanghai"}
```

`startAt` 必须包含明确偏移或Z，服务端规范化为UTC；`timeZone` 为有效IANA时区，用于预览和保存后展示。表单的首次时间按本机时区编辑，并明确提示这一点。间隔按真实经过的小时数计算，跨夏令时仍为3小时，而非每天固定8个当地钟点。保存前预览和保存后的详情都显示频率、下次时间及其时区。

- 首次时间尚未到：下一次为首次时间。
- 首次时间已过：以首次时间为锚点，取严格晚于当前时间的下个周期；不把保存动作当作立即执行。
- 暂停不停止当前执行。恢复保留锚点，跳过暂停期间的周期，从下个周期继续，不从恢复时间重新计时。
- 服务重启保留SQLite中的计划、锚点、下次时间与执行记录。停机漏期沿用现有规则合并补跑一次，再推进到当前时间之后的周期，不展开积压执行。
- 同一到期项沿用原子领取、确定性执行ID和回执幂等规则。上一轮仍在运行或已接收待执行时，本次记为跳过，下一周期继续；当前轮接收未知不会重复发送。各周期的重复业务处理仍需执行任务自己按任务ID与版本去重。
- 默认约15秒扫描一次，需要服务和主机运行；不是严格实时调度。
- 日历按新规则展开未来预计安排，仍受共享1000项读取上限约束，达到上限明确提示不完整；历史只显示实际执行事实。

此能力不自动创建或启用任何业务计划，也不改变员工职责、模型、权限或任务状态。瑞辰职责与真实回归闭环分别属于TASK-113和TASK-114，体验任务自动派工仍限来源可确认的系统自动创建体验任务。

本轮未部署或重启全局服务。已安装服务需部署新Server/Web资产后再做真实创建与触发验收；旧服务会明确拒绝新格式，不能把新Web单独配到旧Server上。

Mac原生端目前没有定时模块；完整原生模块或显式Web入口需要确定交付范围。本轮检查不等于Mac功能验收通过。
