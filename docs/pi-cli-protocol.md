# Pi CLI 大结果与解析断点

Pi CLI 的协议入口由 `pi-protocol-reader.ts` 负责。它按小块进行 SAX 校验，不将整个 JSONL 记录或累计上下文装进内存。`turn_end` 的 context/toolResults、`agent_end` 的旧消息属于 Pi 已持有的历史，不重复存入 Wand；最终助手消息、用量和终态错误仍参与对账。

## 工具结果的展示容量

`result` / `partialResult` 超出保留预算时，`pi-tool-result-preview.ts` 提供明确标注的展示预览。文本保留有界的首尾；不能完整保留的图片改成文本提示，不向客户端发送截断的 base64。content、details 和其他属性分别计量，内容过大不会直接吃掉随后返回的执行信息；不完整的执行清单设置 `inventoryComplete=false`。普通容量以内的工具结果原样保留。

这只影响 Wand 的展示投影，不修改 Pi 实际拿到的工具结果、工具执行或模型上下文。超大图片不在 Wand 预览里完整展示；不能把预览称为完整结果。

原生事件桥在序列化前完成同一投影。旧 JSON/print 链路在写 Server 事件文件前完成投影，再由独立文件读取器驱动会话更新，避免原始图片或冗余上下文先触发文件容量保护。恢复链路使用相同策略。

完整 JSON 仍必须校验通过才发布事件。无效/不完整 JSON、过深嵌套、异常属性名以及超出安全容量的真实助手载荷仍会失败；运行结果不确定时继续禁止自动重发输入。文件仍有独立的磁盘容量和身份保护，并非无限写入。

## 数据库历史与恢复

普通会话历史继续从现有 `command_sessions.messages` / output 读取，无需重新解析 Pi 原始日志。原生 Pi 的进行中回合另外在 `pi_cli_checkpoints` 保存：

- 解析后的当前回合状态、原生 session ID、用量和终态错误；
- 当前请求 ID、运行 incarnation、源文件路径及设备/inode；
- 完整协议记录之后的原生文件字节游标。

状态和游标存在同一个 SQLite 原子值内，至多每秒保存一次。提交前退出只会留下旧断点；提交后退出可以直接从数据库恢复状态。半条记录不推进游标，迟到的旧请求不能写入新回合，较小游标不能覆盖同一回合的新断点。缓存仅用于加速；保存失败不会中断 Pi，也不会触发重做。

恢复时，宿主验证请求、incarnation、文件身份、大小和游标前的换行。验证通过且未读尾部在既有回放窗口以内时，只读取断点之后的数据。终态错误即使对应进程退出码为零也保留。缓存与文件不符、版本不支持或增量超过回放窗口时，使用原有的保守恢复路径，不猜测缺失区间，不重发任务。

旧 terminald/Render JSON 执行宿主没有原生文件字节游标，仍使用已有日志恢复；已经完成的历史同样直接读数据库。旧记录不会在普通 GET 中全表扫描、重建或修改。数据库迁移只增加断点表，不改写用户历史。
