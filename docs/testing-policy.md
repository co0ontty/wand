# 测试服务于需求，不锁死实现

测试的目的是发现重要行为回归，不是替产品决定组件、布局或交互写法。需求、架构和组件库升级可以改变实现；测试与新行为同步调整，不能因为历史断言而拒绝合理需求，也不能通过删除业务断言掩盖真实回归。

## 分层入口

| 层级 | 检查目标 | 执行入口 |
| --- | --- | --- |
| 默认 CI | 类型检查、bundle、业务单测；存储/迁移、权限、输入送达、会话归属、取消/恢复、降级边界、发布完整性 | push / PR 的 `CI / verify`；`node scripts/run-ci-tests.js --suite=unit` |
| UI 专项 | 受影响界面的关键完整流程，输入保留、真实提交结果、取消与权限；必要时检查浏览器兼容性 | 手动 CI 勾选 `ui_regression`；或 `node scripts/run-ci-tests.js --suite=ui` |
| 全量诊断 | 所有现有测试，供跨域改动或问题定位；不表示每个历史断言都是产品规格 | `node scripts/run-ci-tests.js --suite=all`（不传参数保持此行为） |

选定范围内失败仍返回非零退出，不使用 `continue-on-error` 或整套自动重试把失败变绿。UI 专项失败不等于业务单测失败，两者分别报告。界面改动仍须对受影响流程作真实浏览器/原生验收；不需要机械执行所有历史点击矩阵。

## 新增和维护测试的取舍

- 优先断言输入、结果、持久化和失败边界。已有覆盖足够时不另造一套测试。
- 少量端到端流程覆盖关键路径，不为每个点击、图标、动画帧或截图排列组合新增用例。
- 不以源码字符串、类名、组件种类、DOM 子节点顺序、固定坐标、尺寸和文案精确字面值定义功能，除非它本身是当前确认的对外契约。
- 现有源码检查需要逐项判断：安全/协议约束可以保留；布局或实现形态检查改为专项、结果断言或清理。不能按关键词整批删除。
- 自动化工具的鼠标命中或 Chrome 启动问题，先区分测试基础设施与产品失败。记录真实证据，不因此增加生产实现绕路或限定界面结构。
- 不把高覆盖率、测试数量或某套测试全绿等同于需求完成；最终验收仍对应本轮需求。

## 本轮整理范围

- 普通 CI 不再自动启动整套浏览器操作矩阵；业务、协议和运行生命周期测试仍为必过门禁。
- 原生 composer 的源码检查不再限定 HStack/ZStack、48px、padding、send 子节点关系；保留执行态与操作可用性的接线检查，并移入 UI 专项。
- seed markup 结构检查作为当前 Web 迁移实现的专项检查保留，不把三个宿主或固定节点顺序作为所有新方案的先决条件。
- 删除本轮临时增加的三项浏览器底层微测试，撤掉检查工作流源码写法的断言；以一项实际 suite 范围/失败传播测试保证门禁不漏报。
- 既有混合测试不整文件盲删。例如聊天宽度测试包含真实持久化与订阅行为，应保留；其源码实现断言可在对应功能调整时拆分。其余候选清单是后续语义审查入口，不是已确认的无用测试列表。
