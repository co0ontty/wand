# Wand 运行存储自动维护

这项能力随 npm 包的 `dist/` 安装，普通用户不需要 Wand 源码仓库、构建脚本、定时器安装或手动操作。服务默认后台运行，不增加弹窗或清理提醒。服务启动 30 秒后扫描一次，此后每 6 小时扫描；运行日志的大小轮转由写入方即时执行。

Wand 为自己创建的临时文件记录用途和进程租约，正常完成即回收；崩溃留下的目录至少保留 **7 天**。部署设置 `autoCleanupTemporaryFiles` 默认开启，当前统一控制后台废弃临时文件、上传和诊断归档的扫描；写入方日志轮转始终保留。

## 当前范围

- 服务数据目录的 `cache/temporary/`：语音输入和合成检查音频、语音运行时安装的编译工作目录。
- 系统临时目录的用户私有 `wand-transient-<uid>/`：一次性运行的临时策略与中间文件。
- Unix `/tmp/wand-transient-<uid>/`（macOS 的真实路径为 `/private/tmp/`）：`npm test` 的临时工作目录。测试子进程的 TMPDIR/TMP/TEMP 指向本次目录，即使测试漏写了单个 fixture 的清理，整轮正常结束或失败后仍能回收。短路径避免 Unix socket 长度超限。
- 上传：每个用户项目的 `.wand-uploads/`。新上传文件的归属、实际路径及文件身份写入服务数据库，服务重启后仍能检查；只对有记录的文件回收，不搜索用户磁盘猜测无用文件。
- 未完成上传先写入带进程租约的 `upload-stage` 暂存目录；完整接收并通过配额后才以排他创建写入最终位置，成功/失败或连接关闭后回收暂存。进程强杀留下的接收暂存按七天崩溃规则自动回收。
- 系统运行诊断：macOS/file redirection 的 `web.log`、`web-error.log`、`terminald.log`、`terminald-error.log`，以及会话的 `structured-stdout.log`、`structured-stderr.log`、`structured-spawns.jsonl`。每份当前日志最多 **10 MiB**，最多保留 **3 份**轮转归档；归档超过 **14 天**且无占用时后台回收。单次超大诊断块只保留末尾10MiB，完整业务消息仍归会话存储。

根目录和每个工作目录均带版本化归属标记，权限为 0700，租约文件为 0600。清理只接受明确记录的六种临时用途；没有标记的旧 `wand-*` 目录不会仅凭名字删除。被其他进程复用的 PID 会保守地延迟清理。

上传的所属会话、共享工作空间/团队或文件历史/队列引用仍存在时保留；从首次发现无人引用起再等七天。跨目录的PTY/结构化输入会在发送前登记对已成为孤儿文件的引用，未知送达也保护，直到对应会话删除。其他结构化执行正在进行时推迟上传回收；无关的空闲PTY shell不会永久阻塞。用户改动、替换或重定向上传文件后不再自动删除。回收后自动更新上传空间计数。

不清理业务消息、PTY文本/轮转历史、恢复用的原生执行事件、仍被引用的附件、模型、凭据、备份、更新 helper 状态/回滚输入、发布包或第三方应用目录。Linux systemd/journald 的输出继续由系统日志机制管理，不改全局日志策略。当前已经运行的旧terminald继续保留，等其正常升级后才使用新写入轮转，不为清理中断终端。原有[历史构建缓存清理](build-cache-cleanup.md)仅是源码开发者的独立附加功能。

## 管理员排查入口（正常使用不需要执行）

```bash
# 默认预览，不删除文件，也不启动服务或初始化数据库
wand storage:cleanup

# 使用相同的七天规则手动回收
wand storage:cleanup --apply

# 指定实例配置；仍不接受自定义删除路径
wand storage:cleanup --apply -c /path/to/config.json

# 关闭服务的定时清理；下次服务启动生效，正常操作结束时的临时回收仍保留
wand config:set autoCleanupTemporaryFiles false
```

登录管理员可使用 `GET /api/storage-cleanup/status` 查询调度状态与上次实际执行结果、`GET /api/storage-cleanup/preview` 预览、`POST /api/storage-cleanup/run` 执行。POST 仅接受空对象，不接受路径、命令、保留期或扩展范围。GET 不删除文件。连接应用的普通会话/文件权限不能访问这些管理员入口。

结果包含候选数、实际删除数、跳过数、按用途统计（含upload和diagnostic-log）、逻辑字节和分配字节，不暴露临时文件内容或凭据。分配字节不是 APFS 共享块/快照下的净释放保证。上传每轮检查最多100个归属记录，按上次检查时间轮转避免旧引用阻塞其它记录；诊断仅查配置目录及最多1000个会话目录的固定文件名。

## 安全与限制

年龄采用整棵目录最新 mtime/ctime，不只看父目录。创建进程、直接子进程或安装/测试进程组还存在时跳过；有打开文件或 cwd 引用时跳过。删除前重新检查目录身份、进程、路径和最近活动。

遇到符号链接、跨设备挂载、特殊文件、无效归属记录、扫描超限或无法检查打开文件时保留目录。只有明确标记为测试工作目录或语音安装工作目录时允许回收其一次性 Git fixture/固定版本下载源码；其他用途出现 Git 元数据即保留。扫描总计最多 20000 项、深度最多 32 层；单个服务内扫描互斥，关闭等待当前扫描结束并取消未开始的删除。macOS/Linux 的废弃回收需要 `lsof`；Windows 当前只进行正常完成回收，废弃回收会报告检查不可用。

历史遗留的无归属上传/测试目录、旧语音临时目录和外部工具缓存不能由这套机制推定无用。进程被强杀、恰好处在向用户工作目录发布文件与提交归属之间的极短窗口，未获得完整归属记录的目标部分文件保守保留；接收阶段的大部分残留由暂存租约覆盖。未知归属或被替换的日志归档也保留，不覆盖。命令行清理与不同服务实例可能同时检查同一已废弃目录；目录身份和引用复核会使后到者跳过已变化/不存在的对象，不会重建或重复发送任务。
